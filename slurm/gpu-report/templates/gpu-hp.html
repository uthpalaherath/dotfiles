A GPU Eff above 100% is due to Nvidia drivers rounding off sub-process usage on the same GPU. For reporting purposes, treat it as 100% until Nvidia resolves the issue.

The time-weighted GPU efficiency average is calculated as,

TWA GPU Eff = Σj (GPU Effj × Nj × tj) / Σj (Nj × tj)

where Nj is the number of GPUs and tj is the elapsed time of job j.

The usage statistics above include completed, cancelled, timed-out, and failed jobs that utilized the GPUs. GPU efficiency represents the percentage of time GPU compute resources were actively engaged as reported by nvidia-smi. For a detailed, per-user breakdown, you can run the following command on a login node:

$ slurm-gpu report -r gpu-hp -S YYYY-MM-DD -E YYYY-MM-DD -u ${USER}

The detailed Slurm reports for users who utilized the partition during this period are attached to this email. Read our Measuring Efficiency guide to learn how to run your jobs efficiently.

Your institutional high-priority monthly quota will be reset on the first day of each month. To check current usage and balance, run the following command from a NCShare login node,

$ get_gpu_quota_account.sh

If your Time-weighted GPU Eff and/or GPU Mem Eff is below 50% you may consider running those jobs on a lower-tier GPU if you have access to any outside of NCShare. For example, as a full H200 GPU has 141 GB VRAM, a job reporting 34% GPU Mem Eff may be run on an RTX 6000 ADA or an RTX A6000 consisting of 48 GB VRAM. Alternatively, we are always happy to work with you to help optimize your GPU utilization.

The limits for the gpu-hp partition, as set by the governance committee are,

  • 8 concurrent GPUs per-user
  • 7-day max walltime
