A GPU Eff above 100% is due to Nvidia drivers rounding off sub-process usage on the same GPU. For reporting purposes, treat it as 100% until Nvidia resolves the issue.

The time-weighted GPU efficiency average is calculated as,

TWA GPU Eff = Σj (GPU Effj × Nj × tj) / Σj (Nj × tj)

where Nj is the number of GPUs and tj is the elapsed time of job j.

The usage statistics above include completed, cancelled, timed-out, and failed jobs that utilized the GPUs. GPU efficiency represents the percentage of time GPU compute resources were actively engaged as reported by nvidia-smi. For a detailed, per-user breakdown, you may run the following command on a login node:

$ slurm-report -r h200-hp -S YYYY-MM-DD -E YYYY-MM-DD --user ${USER}

The detailed Slurm reports for users who utilized the partition during this period are attached to this email. Read our Measuring Efficiency guide to learn how to run your jobs efficiently.

Your lab's high-priority quota will be reset every 30 days. To check current usage and balance, either log in to your lab's account on Research Toolkits or run the following command from a DCC login node,

$ get_h200_usage.sh <labname>_h200

Your job will terminate as soon as this limit is hit.

If your Time-weighted GPU Eff and/or GPU Mem Eff is below 50%, please consider running your jobs on a different partition. A list of GPU partitions available on DCC can be found here: https://dcc.duke.edu/dcc/partitions. For example, as a full H200 GPU has 141 GB VRAM, a job reporting 34% GPU Mem Eff may be run on an RTX 6000 ADA or an RTX A6000 consisting of 48 GB VRAM. Alternatively, we are always happy to work with you to help optimize your GPU utilization.

The limits for the h200-hp partition, as set by the H200 governance committee are,

  • 8 concurrent GPUs per-user
  • 7-day max walltime

Read the user guide to learn more about using DCC's H200 allocations.
